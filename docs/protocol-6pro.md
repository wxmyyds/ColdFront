# 红魔散热器 6 Pro 协议

本文依据 `/home/WXM/AllProjects/smali` 中的官方 App 静态代码整理。由于没有 6 Pro 实机，文中的结论不能视为硬件验证结果。缺少协议证据的功能不会按 8 Pro 的行为推断。

## 识别与 GATT

官方扫描接受公司 ID `0x08CA`、MSD 前两字节 `[0x05,0x05]` 或 `[0x05,0x06]`，并要求广播服务 UUID `00004a41-0000-1000-8000-00805f9b34fb`。由于型号编码存在重叠，ColdFront 只把名称明确包含 `6 Pro` 且不含 `Plus` 或 `+` 的设备识别为 6 Pro。

6 Pro+ 是独立型号。本次分析使用的官方旧版 App 不支持它，所以本文不描述 6 Pro+ 协议。新版官方 App
（jacket6 V2 架构）已经包含 6 Pro+，其协议见 [6 Pro+ 文档](protocol-6pro-plus.md)。

主控制服务为 `d52082ad-e805-9f97-9d4e-1c682d9c9ce6`。官方要求 `1011`、`1012`、`1013`、`1015`；`1014`、`1016`、`1017`、`1018` 是可选特征。ColdFront 只从主服务绑定 6 Pro 特征，以免误用其他服务中 UUID 相同的特征；`101C`、`101D`、`101F` 属于 8 Pro，6 Pro 不映射这些特征。

## 命令

| 特征 | 用途 | 写入值 |
|---|---|---|
| `1011` | Hall 自动 / 开 / 关 | `01` / `02` / `03` |
| `1012` | 风扇 | 单字节 raw，官方 UI 范围 `0x28..0x50`（40–80） |
| `1013` | 灯效 | `[mode, R, G, B]` |
| `1017` | 超频（Super Mode） | 开 `01`，关 `00` |
| `1018` | 自动温控 | 开 `01`，关 `00` |

`1013` 已确认的模式为：`01` 炫彩、`02` 呼吸、`03+RGB` 单色呼吸、`04+RGB` 常亮、`06` 关闭。`1016` 的业务语义仍未确认，因此 ColdFront 不据此展示或解析状态。命令按表中的原始字节写入，不添加缺少证据支持的校验字段。

官方界面将自动温控与超频设为互斥模式。Hall 三态命令有协议证据，但不同官方界面版本是否显示对应控件仍未确认；ColdFront 暂不提供独立 Hall 设置项。超频和自动温控之间的设备端交互仍需通过实机回归确认。

## 状态与温度

`1015` 使用 `[kind, payload...]` 格式，不采用 8 Pro 的状态标签：

| kind | 含义 |
|---|---|
| `01` | Hall，payload 首字节 `1/2/3` 表示自动/开/关 |
| `02` | 风扇 raw |
| `03` | 灯效数据 |
| `04` | 温度数据 |
| `05` | OutputHasLoad：首字节 `0x80/0x81` 为 true，`0x00/0x01` 为 false；其他值未知 |

官方温度回调只读取通知的首个 signed byte。ColdFront 的 6 Pro 路径不使用 8 Pro 的 `-6°C` 校准，也不使用通用的多字节启发式；温度单位和传感器含义仍未确认。解析时会忽略超出 `-40..80` 的值。

## 待实机确认

- 两组 MSD 在零售 6 Pro 上分别对应什么型号，以及特征属性和通知时序。
- 温度单位/校准、OutputHasLoad 对设备控制的影响、风扇越界值处理和不同固件的灯效 payload 长度。
- 断线重连后的状态同步及 OTA 行为；本文不描述或实现 OTA 协议。
