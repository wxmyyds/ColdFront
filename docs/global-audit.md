- 基线：`bd4ef64`（PR #10 合并后的 main）；工作分支：`audit/global-quality`；PR：[#11](https://github.com/wxmyyds/ColdFront/pull/11)。

## 发现的问题与修复

### BLE / 应用逻辑 / 生命周期

| 问题 | 修复及边界 |
|---|---|
| Activity ViewModel 清理会关闭前台服务正在使用的同一个 GATT；释放后状态仍可能显示已连接 | `BleManagerHolder` 引入显式使用者；最后一个使用者释放才清理。真正清理发布断开状态，进程级管理器可复用。 |
| 旧连接的发现、初始化、轮询任务可能更新或取消新连接 | 会话持有自己的 GATT、特征、任务和命令代次；所有权状态及回调统一在 Main 处理；先失效会话再关闭资源。 |
| 防抖取消在途操作、超时后盲目重试，迟到回调可能确认下一项操作 | 独立 `GattOperationQueue` 保持已接受操作的串行占用；按 owner/target/kind 身份匹配回调。超时关闭歧义会话；只有明确拒绝/失败才重试，并再次验证命令是否有效。 |
| 保存设备直连绕过权限/地址检查，打开失败可能卡在连接中 | 统一连接入口，捕获平台异常，增加连接/发现/初始化期限和失败清理。 |
| 提前发布 CONNECTED，用户关机命令可能被初始化 ON 覆盖 | 必需启动 ON 和初始化尝试结束后才进入 CONNECTED。可选特征缺失或明确拒绝不被当作必需功能；在途超时仍按会话失效处理。 |
| 散热和智能控制共用可取消任务，互相取消 | 分开命令代次，只淘汰尚未执行的旧意图，不取消已接受的硬件操作。 |
| 旧 RGB 请求可能晚于新请求写入；写入回显可能覆盖更新通知 | 在串行执行边界检查最新请求；特征读回版本保护设备通知不被迟到的确认回显覆盖。 |
| 未确认控制立即显示成功 | 写入确认后更新控制状态；风扇单独保留 `pendingFanPercent`，使滑块等待确认时不回跳。 |
| 老型号风扇 raw 大于 127 被当成负数；独立功率字节同样有符号问题 | 统一无符号解析，补充边界测试。 |
| 广播设备以 MAC-only 相等，StateFlow 丢弃 RSSI/名称变化 | 恢复值相等；扫描列表仍显式按地址去重。 |
| 通用 Magcooler 名称规则早于具体 6/8 代匹配 | 具体代数优先，保留 MSD 优先识别。 |
| 旧扫描回调污染新扫描状态 | 每轮扫描绑定独立 callback/scanner，丢弃已失效轮次的事件。 |
| 智能/Boost 初始状态和 RGB 查询缺失 | 按特征能力读取/订阅；发送已记录的 RGB 状态查询，不增加未知协议。 |
| OEM 定位兜底只申请 FINE | 同时申请 COARSE，保留 Android 12 前后的权限兼容。 |

### 服务、启动恢复和快捷磁贴

- NotificationChannel 增加 API 26 保护，保留 API 24/25 支持。
- 服务内部检查连接权限并处理前台提升失败，不能只依赖调用方捕获启动异常。
- 新增独立 `service_profile_id`：普通激活档案不再隐含“开机自动启用”。旧安装缺少此键时默认关闭；明确启用、停止/切手动分别保存和清除意图。
- 冷启动等待匹配设备初始化完成后再发智能控制；`setSmartAndAwait` 返回确认结果。
- null Intent 的 sticky 恢复只读取明确保存的目标；Boot 使用恢复动作而不是重写过期的启动快照。
- START/STOP 命令串行处理，使用 startId 防止较早 STOP 丢掉后来 START。
- 手动关闭限定目标地址，不误操作用户后来连接的另一设备；失败给出反馈，而不是声称硬件已关闭。
- Home 关闭服务所属设备的智能控制时同步撤销后台恢复意图。
- 补齐磁贴 `QS_TILE` intent-filter；磁贴显示当前 BLE 智能状态，而非 Service 实例是否存在。
- 断线和激活失败提供明确重试动作。没有添加无限后台自动重连循环。
- 通知使用当前应用语言，并避免相同内容重复更新。

### 数据、状态和 UI

| 问题 | 修复 |
|---|---|
| 相同 MAC 重复建档；失败连接也落盘；诊断/已保存设备路径漏更新 | 所有路径统一在成功会话事件后 `recordConnection`，事务内按规范化 MAC 合并并激活，保留已有名称/ID/设置。 |
| 活跃档案查询读了两个不一致快照；保存/激活不是一个事务 | 查询单一 Preferences 快照；保存与激活原子提交。 |
| 删除连接中的档案后，成功回调重新建档 | 序列化删除和连接记账，忽略已删除会话的后续建档；仅断开同一个仍在连接中的会话。 |
| 一个损坏 JSON 项隐藏整份列表；未知旧型号在后续保存时被删除 | JSON 编解码移入 data；逐项解析，保留未知/坏项和未知字段；整份损坏时拒绝覆盖，并报告 I/O 错误。 |
| DataStore I/O 错误终止状态收集或成为未捕获异常 | UI 读流保留最后值并重试；写错误可见反馈；协程取消不被吞掉。 |
| RGB 页面未观察到中间 SENT+同值事件，草稿永久脏状态 | 匹配请求完成后允许跟随最新设备数据；新草稿/其他请求/失败请求仍受保护。 |
| 扫描成功留下 `[Home, Devices, Home]` | 返回已有根 Home；Scan/About 导航采用 singleTop。 |
| 固定 12dp 底部 inset 不能覆盖较大的系统导航区 | 实际 navigationBars inset 与 12dp 最小值取并集；保留横向 inset。 |
| 短高度导航 rail 可能裁切 | 仅 rail 内容可滚动，不移动或重建 NavHost。 |
| RTL 下弹窗按压锚点被镜像两次；键盘重复使用旧手指位置 | 物理左上角绝对锚点；匹配原生 press/release，非指针操作采用行下方稳定锚点。仍保持原菜单样式、动画和触摸反馈。 |
| 开关行缺少明确 Switch role | 补充语义，不增加第二个点击处理器。 |
| 旋转后扫描重试 callback 丢失，按钮无可用操作 | 显示可执行的“重新扫描”兜底。 |
| 已保存设备连接失败没有对应反馈 | 在失败目标的设备卡显示错误。 |
| About 浏览器 Intent 无处理程序时崩溃 | 捕获 ActivityNotFoundException，显示可恢复提示。 |
| Compose 通过非观察式 Locale 格式化日期 | 读取 LocalConfiguration 的 locale；中英文覆盖设置保持原含义。 |
| 常亮/关闭预览仍运行无用无限动画 | 只为需要呼吸或彩虹效果的分支建立动画。 |

### Theme

- 修正 `inversePrimary` 错映射为普通 `primary`；Fixed 强调色族与当前调色板一致。
- 色板生成改为纯函数并按 seed/dark/palette 记忆，避免无关重组重复生成。
- 保留页面浅 `#EFECF6` / 深 `#191920`、选项浅 `#FBF9FE` / 深 `#2B2B34`，以及原字体、形状与 Expressive motion。
- 测试覆盖三种 palette、多个 seed、两种明暗下的固定表面、文字与 inverse 对比度。RGB 实色、品牌资源的字面色不视作一般主题硬编码错误。

## 解耦与清理

- `GattOperationQueue.kt`：纯串行/回调关联逻辑与 Android 连接管理分开，可确定性测试超时、取消和过期回调。
- `CoolerTelemetryParser.kt`：设备字节解码与 GATT 生命周期分开；保留温度旧行为。
- `data/ProfileJson.kt`：持久化格式从 domain 模型移回 data，保留现有 JSON 字段格式。
- 删除不再使用的 `ThermalThresholds`、阈值流/更新/键、旧 service RGB 入口及 Service 实例暴露、旧 `setFanMode` 转发、旧建档工厂、重复依赖别名。
- 删除 40 个无调用字符串槽位及中英文实现；新增实际错误处理文案。不删除仍使用的设备/OEM/旧 API 兼容分支。
- 删除没有实现调用的精确闹钟和 Wake Lock 权限；旧 DataStore 阈值值留在磁盘，不进行破坏性清理。
- 更新 README 中过期的主机温控、动态色默认值、版本和目录描述。
- 没有把每个页面换成单独 ViewModel 或给已有桥接类增加接口层。新结构调整都有上表对应问题。

## 无法安全确定或尚未验证

1. **真实 BLE 和旧固件兼容**：没有散热器/Android 实机；订阅能力、初始化时序、8 Pro 和旧型号端到端命令、系统权限撤销/开关与后台行为仍需设备回归。队列超时现在会明确结束坏会话，需确认各固件的合理时限。
2. **温度校准冲突**：协议资料一处写无偏移，当前实现及另一处写 −6°C。保留现有校准和测试，明确标注待对照；没有宣称已修复物理温度准确性。
3. **UI 实际渲染**：横竖屏、大字体、三键/手势导航、RTL 菜单首次定位、TalkBack、预测返回进度与动效需要实机。现阶段是约束和源码检查，不是截图验收。
4. **系统生命周期端到端**：API 24/25 服务、OEM 蓝牙广播、进程被杀后的 sticky 恢复、开机启动限制和快速 START/STOP 仍缺仪器测试。已有纯数据/队列测试不能替代它们。
5. **存储介质完全损坏**：不会默默覆盖档案，但不会自动猜测恢复坏文档；持续读失败会保留最后可用状态并反馈。若停止时连保存 opt-out 都失败，不能保证下次开机读到清除后的意图；日志明确记录该异常。
6. **不支持的历史设备类型**：记录原样保留但不自动映射到猜测的新型号，仍不展示为可控制设备。
7. **没有新增无人值守无限重连**：断线后提供重试；是否需要退避自动重连属于后续产品/硬件策略。
